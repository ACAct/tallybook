## 提交内容

| 文件 | 职责 |
| --- | --- |
| `app.py` | `main()` 解析 `--port`、`--data`、`--no-browser`，检查端口范围，启动服务并处理启动失败与退出 |

服务包含 dashboard、新增、修改、删除、JSON/CSV 导出和 JSON 导入路由。Host/Origin 白名单使用当前端口对应的本机地址；静态资源仅开放首页、JS、CSS 和 favicon。响应包含 CSP、`X-Content-Type-Options`、`Referrer-Policy`、`Cache-Control`；JSON 请求体限制为 64 MiB，接口错误返回 `{"error": "..."}`。

本次从本地 `qingji` 项目提取已有 D1 参考实现，并使用 Codex 协助整理、运行测试和提交。上述代码不是本次从零独立编写，不据此虚构个人开发过程或博客成果。

## 实际验证

环境：Windows、Python 3.13.0。测试日期：2026-11-07。

在本地完整 `qingji` 项目目录运行：

```powershell
$env:PYTHONUTF8 = '1'
python -m unittest discover -s tests -p test_server.py -v
python -m unittest discover -s tests -v
```

D1 验收 **4/4 通过**：

- `test_full_api_flow_and_filters`：新增、筛选统计、JSON 导出、重复导入、删除。
- `test_bad_input_and_cross_origin_blocked`：非法输入返回 400，非法 Origin/Host 返回 403。
- `test_private_files_are_not_served`：数据目录、源码与路径穿越形式均不能经 HTTP 读取。
- `test_largest_valid_backup_fits_import_limit`：最大笔数与字段长度构造的备份小于 `MAX_BODY`。

同一完整项目全套测试复测结果：**13/13 通过**。这些结果来自已有完整依赖的本地项目，不表示仅有 D1 文件的分支可以独立运行；上述 4 个用例也未覆盖所有路由、响应头和启动参数的独立断言。

首次在默认编码下运行全套测试时有 2 项错误：一项因测试读取 UTF-8 文件时使用 GBK 默认编码失败；另一项在并发文件锁处出现 `PermissionError`。开启 `PYTHONUTF8=1` 后全套复测通过。该次通过不能证明并发锁问题已经修复，本次未修改 A3 存储模块。
